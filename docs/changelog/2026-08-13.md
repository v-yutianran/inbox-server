# 2026-08-13 Changelog

### ops(worker)：启用并验收线上 ima Markdown 镜像

**改了什么**：

- 在 Sealos `ns-tbs948af` 创建独立 Opaque Secret，仅保存 `IMA_OPENAPI_APIKEY` 与 `IMA_OPENAPI_CLIENTID`；两个键均非空，验收过程未读取或回显其值。
- Worker StatefulSet 追加该 Secret 的 `envFrom` 引用，并将 `IMA_MIRROR_ENABLED` 从 `false` 切换为 `true`；mihomo、WARP 及其它配置保持不变。
- 使用不含个人数据的合成 Markdown 执行一次真实 ima 镜像，并以相同来源 URL 再执行一次验证幂等。

**如何验证**：

- Kubernetes server-side dry-run 确认补丁仅影响主容器的 Secret 引用与 ima 开关；实际应用后 generation 与 observedGeneration 均为 47，currentRevision 与 updateRevision 一致，readyReplicas 与 updatedReplicas 均为 1。
- Pod 最终三个容器均 Ready；`/healthz` 与 `/readyz` 均返回 200，browser、mihomo、warp 状态均为 `ready` 且 `canAcceptWork=true`。
- 首次合成 Markdown 镜像产生 5 次远程请求，并产生低基数事件 `article.ima_mirror.succeeded`、`stage=complete`、`result=succeeded`。
- 相同来源 URL 第二次镜像产生 0 次远程请求，证明 `/data/ima-mirror` 持久化完成标记生效。

**结果与残余风险**：

- ima 线上镜像与重投幂等验收通过；验证输出不包含凭据、Markdown 正文、文件名、知识库 ID 或第三方响应正文。
- 冷启动期间 mihomo 与 WARP 各因既有 startup probe 时序重启 1 次，随后自行恢复；主 Worker 未重启，最终 StatefulSet rollout 成功。该启动时序不影响本次 ima 验收结论，但后续可单独优化。
- Cloudflare Access 的匿名重定向、Google/邮箱入口与登录后 API Key 解锁仍属于 OpenSpec 5.2，未在本次重复验收。
