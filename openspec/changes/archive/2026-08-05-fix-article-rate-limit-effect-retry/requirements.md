# 文章队列限速与 effect 重试安全需求

## 目的与读者

本文供产品、架构、开发和验收人员共同确认 TypeScript Cloudflare Queue / Sealos Worker 的文章任务重试语义。目标是在不改动既有限速额度和文章归档业务的前提下，消除“限速延期被当作失败、随后被自身 effect 租约阻塞并进入 DLQ”的竞态，并为变更上线后的新文章任务建立可恢复边界。

维护入口为 OpenSpec change `fix-article-rate-limit-effect-retry`；规范性行为以 `specs/article-queue-retry-safety/spec.md` 为准。

## 核心结论

1. 内部限速和有效的 effect 竞争都是“延期”，不是“失败”。
2. 延期不得消耗三次失败预算，不得新增 DLQ，不得提前执行外部归档。
3. 尚未开始外部请求的限速延期不得遗留阻塞自身重试的 effect `processing` 状态。
4. 变更生效后的新文章任务必须保留受控重放材料；仅含 digest 的历史 DLQ 不自动恢复、不删除、不改写。
5. 验证默认使用合成数据；生产历史 DLQ 和真实用户文章只能只读核对，除非用户另行明确授权。

## 背景事实

- 当前文章任务处理链先领取 effect，再检查日限额和窗口限额。
- 内部限速拒绝会被分类为可重试失败，但 effect 仍保持 `processing`，有效期为 10 分钟。
- Queue 失败重试从约 30 秒开始，任务下一次领取 effect 时可能得到 `busy`；失败预算最多为 3 次，因而可能错误进入 DLQ。
- 当前历史 DLQ 保存任务标识、去重标识、类型、尝试次数、错误摘要和 payload digest，但不保存可重放的原始任务信封。
- 已知生产重放期间新增 15 条相关 DLQ 只作为问题证据；本需求不据此假定其原始 payload 可恢复。

## 范围

### In Scope

- `dispatch-item` 中 `itemKind=article` 的内部限速、effect 租约、Queue 延期、失败预算与 DLQ 行为。
- 文章任务在 Worker 重启、Queue 重投和并发租约竞争下的幂等行为。
- 变更生效后新文章任务的耐久恢复材料及经过认证的运维重放边界。
- 与上述行为直接相关的结构化日志、指标和合成数据验收。

### Out of Scope

- 调整日限额、窗口限额、限速周期或文章正文最小长度门槛。
- 修改 Defuddle、Playwright、微信公众号抓取、Git 提交或仓库目录规则。
- 删除、清空、批量重放或人工补全任何历史 DLQ。
- 从 digest 反推历史 URL、标题、标签、正文或任务 payload。
- 改变 link、text、file 的业务结果；共享基础设施改动不得造成其回归。
- 处理由真实外部请求产生的 `uncertain` effect；该状态继续禁止自动重复副作用。

## 术语

| 术语 | 定义 |
| --- | --- |
| 内部限速 | Worker 在调用外部归档目标之前，通过控制面检查的日限额或固定窗口限额。 |
| 延期 | 当前不执行外部副作用、保留任务可再次投递资格且不消耗失败预算的队列结算。 |
| 失败预算 | 只针对真实执行错误累计、用于决定 retry 或 DLQ 的最大尝试次数。 |
| effect 租约 | 防止同一任务对同一目标并发或重复产生外部副作用的执行资格。 |
| 恢复材料 | 能重建任务信封的耐久数据，不包括仅可校验但不可逆的 payload digest。 |
| 历史 DLQ | 修复部署前已经存在的 `worker_dead_letters` 记录。 |
| 新文章任务 | 修复部署并完成必要迁移后首次被系统接收的文章任务。 |

## 需求清单

| ID | 需求 | 验收结果 |
| --- | --- | --- |
| ARRS-001 | 内部限速拒绝 SHALL 形成无损延期。 | 失败尝试数不增加、DLQ 不增加、无外部调用。 |
| ARRS-002 | 任务 SHALL 不早于控制面给出的 `retryAt` 恢复执行。 | 提前投递只再次延期；到期后可继续。 |
| ARRS-003 | 限速延期 MUST 不留下阻塞自身后续重试的活跃 effect。 | 到期重试不会因上一轮延期得到自身 `busy`。 |
| ARRS-004 | 有效的 effect `busy` MUST 形成无损短暂延期。 | 不占失败预算，不写 DLQ，不重复外部调用。 |
| ARRS-005 | 同一文章任务对同一目标 MUST 至多产生一次已确认副作用。 | 重投、重启和竞态下外部成功调用计数为 1。 |
| ARRS-006 | 新文章任务 MUST 在最终 Queue ack 前持久化可重放任务信封。 | 真实失败进 DLQ 后可经认证流程恢复相同任务。 |
| ARRS-007 | 历史 DLQ MUST 原样保留且不得自动重放。 | 部署前后记录及字段逐项一致。 |
| ARRS-008 | 日志 MUST 区分延期、真实失败、恢复完成与最终 DLQ。 | 可按稳定 `event` 和任务关联标识重建状态序列。 |
| ARRS-009 | 日志、Console、公开 API MUST 不暴露恢复材料和敏感文章数据。 | URL、标题、Cookie、令牌与 payload 不出现在输出。 |
| ARRS-010 | 修复 MUST 不改变既有限速额度和非文章任务结果。 | 配置快照一致，link/text/file 回归用例通过。 |

## 业务规则与不变量

### 状态分类

| 事件 | 分类 | 失败预算 | DLQ | 外部调用 |
| --- | --- | --- | --- | --- |
| 内部限速拒绝 | 延期 | 不增加 | 不写入 | 不执行 |
| 另一个有效执行者持有 effect | 延期 | 不增加 | 不写入 | 当前执行者不执行 |
| Queue 在 `retryAt` 前重新投递 | 延期 | 不增加 | 不写入 | 不执行 |
| 外部网络、429 或可重试服务错误 | 真实失败 | 按既有策略增加 | 预算耗尽后写入 | 可能已发起 |
| 明确的永久错误 | 真实失败 | 按既有策略处理 | 可写入 | 视失败点而定 |
| 外部结果不确定 | `uncertain` | 不自动重放 | 保留审计 | 禁止再次自动执行 |

### 限速不变量

- `retryAt` 是当前限速窗口重新允许尝试的绝对时间下界。
- Queue 能力不能一次延迟到 `retryAt` 时，可以多次延期，但任何一次延期都不改变失败预算。
- 延期次数不等于处理尝试次数；运维指标必须能区分两者。
- 同一任务同时命中多个内部限速时，恢复时间不得早于所有适用窗口均允许执行的时点。

### 租约与副作用不变量

- effect 执行资格只保护可能发生外部副作用的阶段。
- 未发起外部请求的限速延期不能遗留一个有效期长于 Queue 重试间隔的自阻塞 effect。
- 已完成 effect 的 Queue 重投只做幂等结算。
- `uncertain` 不能自动转为可再次执行；需要独立、经授权的人工核对流程。

### 持久化与恢复不变量

- 新文章任务在最终成功或明确处置前必须存在可重建的耐久任务信封。
- payload digest 仅用于一致性验证，不得作为恢复材料。
- 恢复必须沿用原任务的稳定去重语义，禁止通过生成新去重键绕过幂等保护。
- 历史 DLQ 数据迁移只能做兼容读取或增加独立关联信息，不得覆盖原字段。

## 可验证验收标准

| AC | 关联需求 | 验收场景 | 判定条件 |
| --- | --- | --- | --- |
| AC-01 | ARRS-001/002/003 | 合成文章任务命中窗口限额，再在 `retryAt` 前后分别投递。 | 到期前无外部调用、无失败计数和 DLQ；到期后成功执行一次。 |
| AC-02 | ARRS-001/002 | 合成文章任务命中日限额，等待期超过 Queue 单次最大延时。 | 经多次延期仍无失败计数和 DLQ，最终可执行。 |
| AC-03 | ARRS-004/005 | 两个执行者竞争同一文章 effect。 | 只有一个执行外部调用，另一个无损延期。 |
| AC-04 | ARRS-005 | 外部成功后、Queue ack 前模拟 Worker 退出并重投。 | 重投不再次调用外部目标，最终任务为完成。 |
| AC-05 | ARRS-006 | 新任务连续触发真实可重试失败直至 DLQ。 | DLQ 可通过认证内部流程恢复完整信封并按相同去重标识重放。 |
| AC-06 | ARRS-007 | 在迁移前后读取历史 DLQ 快照。 | 行数、主键、错误摘要、digest 和创建时间一致，无自动重放事件。 |
| AC-07 | ARRS-008/009 | 收集延期、恢复和 DLQ 日志及 API/Console 响应。 | 状态链完整；不含 URL、标题、Cookie、令牌或 payload。 |
| AC-08 | ARRS-010 | 运行 link/text/file 既有队列测试并比对限速配置。 | 行为与配置无变化。 |

退出门槛：AC-01 至 AC-08 全部通过，且生产部署前只使用合成任务完成自动验证；若需要线上真实任务验证，必须另行取得用户明确授权并使用隔离或可回滚方式。

## 真实数据安全边界

- 自动测试、迁移验证和部署冒烟默认只使用合成 URL、标题、标签和 payload。
- 未经另行授权，不连接生产 DLQ 执行写操作，不发布历史消息，不删除或修改记录。
- 可进行只读核对时，只读取计数、不可逆标识、状态和时间等最小元数据，不在日志或报告中回显真实 URL、标题或正文。
- 新增恢复材料不得通过公开 API 或 Console 返回；访问必须复用经过认证的内部运维边界，并记录不含 payload 的审计事件。

## 禁止事项

- 禁止把内部限速包装成普通 `TypeError` 后沿用失败预算。
- 禁止用缩短全局 effect 租约有效期来掩盖竞态，而不证明并发副作用安全。
- 禁止清空限速桶、改大限额或删除 DLQ 作为修复验证。
- 禁止为恢复历史任务猜测、抓取或逆向原始 URL。
- 禁止在日志、测试快照、PR 描述或验收报告中保存真实 payload。

## 未决项

当前无阻塞实现的产品未决项。以下事项明确留在架构阶段选择，不改变本需求的行为契约：

- 延期语义由“限速先于 effect claim”还是“可回滚的 effect 状态迁移”实现。
- 恢复材料使用现有 D1 表扩展、独立表或等价耐久引用。
- 超过 Queue 单次最大延时的等待采用分段延期还是控制面调度。
- 新任务成功后的恢复材料保留时长与清理机制；无论选择为何，幂等终态必须保留。
