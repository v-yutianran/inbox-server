## 背景与问题

### 已确认事实

- 当前生产由 Cloudflare Pages Console、Cloudflare API、D1/Queues/Cron，以及 Sealos 单副本 headed Chromium Worker、Mihomo、WARP 组成；本次不改变该架构边界。
- 生产 API 自定义域为 `inbox-api.yutianran.cn`。2026-08-03 只读核对时，API `/healthz`、`/readyz` 与 Console 均返回 HTTP 200；未携带管理凭据访问运维、队列与 DLQ 接口返回 HTTP 401。
- 2026-08-03T00:46:21Z 前后的可漂移 D1 基线为：任务 `dead=224`、`deferred=93`、`done=4912`、`failed=1`、`processing=1`，DLQ 记录 `238`，重放操作 `0`，数据库大小 `8,540,160` 字节，Worker 心跳仍在更新。
- 以上线上数值会随生产处理变化，只用于说明风险和建立验收输入，不是永久阈值。验收时必须重新冻结带时间戳的只读快照。
- 当前已具备结构化事件、Worker 心跳、健康端点、固定镜像摘要、任务租约、幂等处理、DLQ 与逐条重放基础；但尚未形成分层 SLO、趋势告警、DLQ 全量解释、数据保留、统一发布证据和可重复恢复闭环。
- 当前 DLQ 与 dead job 相差 14 条，且没有重放操作记录；差异原因尚未形成经验证的全量分类报告。
- 迁移计划中的旧 Docker Compose 回滚演练尚未完成；不得把“当前可访问”视为“可恢复、可重复发布”。

### 业务问题

1. 总览在线不能区分 API、Worker、浏览器、Mihomo、WARP 各自的失效域，浏览器长任务还可能影响探针响应。
2. 运维人员缺少趋势、阈值、最老任务年龄和稳定关联标识，异常发生后难以回答开始时间、影响范围、原因、恢复与回滚结果。
3. 积压、延迟任务和 DLQ 有操作入口但缺少全生命周期治理；未经分类的重放或清理可能产生重复副作用或破坏审计。
4. Cloudflare 与 Sealos 的发布单元不同，现有人工步骤尚不能以相同输入完成预检、发布、验证和回滚，也没有统一证据。
5. 单副本 Worker 存在明确可用性上限，但启用多副本前尚无容量、租约、幂等、归档冲突和登录态隔离证据。

## 目标与成功指标

| 目标 ID | 目标 | 成功指标 |
| --- | --- | --- |
| OBJ-001 | 让各生产失效域可独立发现和定位 | Console、API、Worker、浏览器、Mihomo、WARP 均有可计算状态；P0 验收连续 24 小时无工作负载导致的探针超时 |
| OBJ-002 | 让异常可度量、可关联、可告警 | 核心 SLI 均提供当前值、趋势、阈值、采集时间和部署版本；告警与恢复通知演练均成功 |
| OBJ-003 | 建立安全的积压、DLQ、重放与保留闭环 | 验收冻结快照中的 DLQ 与任务状态差异 100% 分类；所有真实重放与清理均先通过同参数 dry-run 并留下审计 |
| OBJ-004 | 使发布与回滚可重复、可证明 | 每个生产单元均能以固定版本完成预检、发布、验证和回滚演练；任一前置门禁失败时线上版本不变化 |
| OBJ-005 | 明确单副本容量与恢复边界 | Worker 恢复演练 RTO 不超过 15 分钟；形成经证据支持的容量上限、降级规则及是否提出多副本 ADR 的结论 |
| OBJ-006 | 保护凭据、用户数据和外部目标 | 自动验证不使用真实用户数据、不写真实外部目标；日志、指标、告警、发布证据与 Console 中敏感信息泄漏数为 0 |

## 非目标

- 不改变采集源、分发目标、公开 API 路径、文章提取优先级、归档格式、去重、限速额度或既有业务语义。
- 不在本变更中直接增加 Worker 副本，不替换 D1、Cloudflare Queues、Pages、Sealos、Mihomo 或 WARP，不引入服务网格。
- 不把第三方 APM、Cloudflare Access 或某个具体告警渠道设为完成本变更的前置条件。
- 不删除、清空、批量重放或改写现有 DLQ、旧 Python 运行时、旧 Docker 数据或生产历史记录。
- 不使用真实用户数据、真实文章、真实凭据或真实外部目标执行试验性恢复、压测或 canary。
- 不在本需求文档中规定类、函数、表结构、框架、脚本实现或具体技术选型。

| --- | --- |
| 生产运维人员 | 查看状态和趋势，接收告警，执行经授权的 dry-run、重放、清理、发布与回滚 |

| Console | 向已认证运维人员展示聚合状态、趋势、阈值和证据，不承载敏感 payload |
| Cloudflare API / D1 / Queues / Cron | 提供控制面、状态、队列和调度能力，是独立生产失效域 |
| Sealos Worker / 浏览器 / Mihomo / WARP | 执行采集、分发和文章归档，是独立生产失效域；当前保持单副本 |

## 范围

### 包含项

- 分层健康状态、业务进展状态、稳定事件、核心 SLI/SLO、趋势和告警。
- 队列积压年龄、延迟任务、DLQ 一致性、逐条安全重放、清理 dry-run、保留审计。
- Cloudflare Console/API、D1 migration、Sealos Worker/Mihomo/WARP 的发布证据、失败停止和回滚。
- 使用合成数据和隔离目标的线上 canary、容量基线、成本趋势、备份恢复和单副本边界。
- 必需配置校验、权限隔离、敏感字段禁漏和真实数据使用边界。

### 排除项

- 采集、解析、分发、文章归档等业务功能变更。
- 未经批准的生产数据写入、历史消息重放、数据删除、旧资产删除或生产部署。
- 多副本或外部可观测平台的实际引入；如后续批准，须另建 ADR 与变更。

## 业务规则与状态

### 健康状态规则

| 状态 | 业务含义 | 任务领取规则 |
| --- | --- | --- |
| `starting` | 进程已启动但必需依赖或运行条件尚未全部可用 | 不领取依赖未就绪能力的新任务 |
| `ready` | 进程、依赖与任务领取条件均满足 | 可按既有规则领取任务 |
| `degraded` | 进程可响应，但部分依赖、进展或 SLO 异常 | 仅领取不受异常影响的任务；其余延期或停止领取 |
| `stopping` | 已收到停止指令并进入收尾 | 禁止领取新任务，已领取任务安全结算或释放 |
| `failed` | 无法提供其职责范围内的能力 | 不领取任务，触发告警和恢复流程 |

- 单一“在线”不得替代分层状态；状态必须带采集时间，过期数据不得展示为当前正常。
- liveness 不得因单个业务任务耗时而失败；readiness 必须反映任务领取能力和依赖状态。
- `degraded` 不等于自动重启；是否重启由故障类型、恢复策略和风险决定。

### 运维写操作规则

1. 先确定精确对象、参数、权限和影响范围。
2. 对同一对象和参数执行 dry-run；dry-run 不得写数据、发消息、部署、回滚或触发真实目标。
3. dry-run 通过后由已授权人员显式执行；执行参数不得静默变化。
4. 执行后必须核对结果、状态、外部副作用和审计记录；核对失败则操作失败，不得宣告完成。
5. 重放默认逐条审核；批量能力不得绕过逐条验证、幂等、限速和审计。

### 数据保留规则

- 在期限获批准前，只允许生成报告和 dry-run，不允许真实删除。
- 初始评估假设为：心跳 7 天，完成任务和任务信封 30 天，DLQ、重放审计和幂等记录 90 天；这些值不是永久政策。
- 最终保留期不得短于最长重试、幂等保护、审计、备份与争议处理所需窗口。
- 清理必须按已批准状态和期限选择，分批、可中断、可对账；禁止无条件清表。

### 发布与回滚规则

- Console、API、数据迁移和 Worker 是独立发布单元，但同一次发布必须共享一份完整证据。
- 发布前置门禁任一失败即停止，不允许跳过后继续其他生产变更。
- 数据变更必须保持跨版本兼容；不得把破坏性回退作为常规回滚前提。
- 未经授权，不得把隔离回滚演练扩大为真实生产切换或旧资产删除。

## 数据、安全与权限边界

| 数据类别 | 允许用途 | 禁止位置或行为 |
| --- | --- | --- |
| 运行摘要 | 状态、时间、低基数类型、不可逆关联标识、部署版本、聚合计数和耗时 | 不得借关联标识还原用户内容 |
| 敏感凭据 | 仅由受控 Secret 或受控文件挂载供获授权运行单元使用 | 日志、指标、告警、Console、发布证据、构建产物和长期浏览器存储 |
| 用户/业务内容 | 正常业务处理；验收仅使用合成替代物 | canary、压测、试验性恢复、测试夹具、验收报告和运维遥测 |
| 恢复材料/任务信封 | 仅用于受认证的完整性校验和受控重放 | 公开 API、Console、普通日志、告警或 PR 文本 |
| 生产历史记录 | 默认只读统计与不可逆摘要 | 未授权重放、删除、修改、复制到隔离环境或反推 payload |

- API Key、Worker 服务令牌、加密密钥、Cookie、浏览器 storage state、文章正文、真实 URL/标题和通知内容均按敏感信息处理。
- Console 管理凭据不得进入构建产物、日志或长期浏览器存储；会话结束或锁定后应不可继续使用。
- 自动 canary、压测和恢复演练必须使用合成数据与无副作用目标；真实数据或生产写入验证需要另行明确授权。
- 告警和审计既要可关联，也不得保存高基数业务内容或敏感字段。

## 非功能需求

| ID | 维度 | 要求 |
| --- | --- | --- |
| NFR-001 | 可用性 | 长耗时业务任务不得阻塞健康响应；P0 发布前连续 24 小时无探针超时 |
| NFR-002 | 可恢复性 | Worker 恢复演练 RTO 不超过 15 分钟；所有回滚均有版本、数据兼容和关键流程证据 |
| NFR-003 | 安全与隐私 | 对日志、指标、告警、Console、API 响应和发布证据执行敏感哨兵扫描，命中数必须为 0 |
| NFR-004 | 可观测性 | 关键事件使用稳定名称、中文描述、关联标识、结果和时间；任何当前状态均带采集时间和部署版本 |
| NFR-005 | 可测试性 | 自动验收仅使用合成数据、隔离存储或替身外部目标，可重复执行且不会产生真实副作用 |
| NFR-006 | 兼容性 | 不改变既有公开 API 与采集、分发、归档业务结果；数据变化支持跨版本读取和非破坏性回滚 |
| NFR-007 | 成本 | 指标和事件保持低基数并有保留边界；P2 形成月度成本基线和预算告警依据 |

## 依赖与边界

- 依赖现有 Cloudflare Pages、Worker、D1、Queues、Cron，Sealos、Worker/Mihomo/WARP、Secret 和固定版本发布能力保持可用。
- 依赖现有任务租约、幂等 effect、恢复信封、重放、结构化事件和管理认证作为业务基础；技术设计可调整内部实现，但不得削弱其外部行为。
- 依赖连续 14 天脱敏生产基线，才能批准最终 SLO、错误预算、保留期、容量和成本阈值。
- 依赖隔离环境、合成 fixture、无副作用目标和可恢复备份，才能执行自动 canary、压测和恢复演练。
- 真实生产写入、真实历史重放、数据清理、部署、回滚、旧资产删除和自动化 E2E 均受单独授权边界约束；本需求不扩大授权。

## 风险

- 事件和指标增加存储与查询成本：限制为低基数运行摘要，并以保留报告和月度成本趋势约束。
- 健康检查与工作负载隔离后可能只证明进程存活：readiness、业务进展时间和 SLO 必须共同判断。
- 重放可能重复外部副作用：逐条验证完整性、幂等、effect、限速和当前目标状态，默认不批量执行。
- 清理可能破坏重试、去重和审计：未经 14 天 dry-run、期限批准和对账不得执行。
- 单副本仍是可用性瓶颈：用 RTO、备份、容量告警和降级降低风险，多副本另行决策。

## 待确认事项

以下开放问题均不阻塞已批准的总体技术设计；技术设计应保留相应验收门禁。它们只阻塞对应生产阶段的最终参数冻结或执行：

1. **OPEN-001 告警渠道与接收责任人**：在 P1 告警投递验收前确认首选渠道、接收人和可达时段。
2. **OPEN-002 最终 SLO、错误预算和告警窗口**：在连续 14 天基线后批准；批准前不得作为自动处置依据。
3. **OPEN-003 最终数据保留期限**：在 14 天 retention dry-run 后批准；批准前禁止真实清理。
4. **OPEN-004 生产 RPO**：在平台备份能力和隔离恢复证据完成后批准；批准前不得宣告生产恢复目标达成。
5. **OPEN-005 多副本路线**：容量与并发安全验收后选择 active-passive、任务分片或继续单副本；属于后续 ADR 决策，不阻塞本变更 P0/P1。
6. **OPEN-006 Cloudflare Access 或外部 APM**：均为可选增强，若决定引入，须另行需求与 ADR，不影响本变更使用现有认证和原生数据面完成。

会阻塞下一阶段总体技术设计的待确认项：**无**。
